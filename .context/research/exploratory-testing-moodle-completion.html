1. Resumen Ejecutivo

3 bugs encontrados con severidad Alta o Crítica. El sistema de completitud de cursos en el Campus Virtual UNC presenta fallas estructurales que impiden a los estudiantes progresar y obtener certificados. Los hallazgos impactan directamente la integración con el DTS.
Total de bugs3
Críticos1 — los cursos no tienen criterios de completitud configurados
Alta2 — completion tracking no registra; checkmarks falsos en UI
Impacto en DTSCrítico — sin completion tracking, la API no puede detectar cursos completados → motor de reglas DTS no puede validar equivalencias → estudiantes nunca quedan habilitados para el examen final

2. Bugs Encontrados

🐛 BUG-001: Cursos sin criterios de completitud (Course Completion Criteria Not Set)

CRÍTICA

Ubicación: Curso 276 (Python Certificación 2) · Curso 159 (Inteligencia Artificial)

Evidencia API:

GET /webservice/rest/server.php?wsfunction=core_completion_get_course_completion_status
     &userid=154814&courseid=276

→ {"errorcode":"nocriteriaset","message":"No completion criteria set for this course"}
→ Course 159: MISMO ERROR "nocriteriaset"

Descripción: Ambos cursos en los que el usuario nelthor está inscripto (Python Certificación 2 e Inteligencia Artificial) no tienen configurado ningún criterio de completitud a nivel de curso. Esto significa que Moodle nunca podrá marcar estos cursos como "completados", sin importar cuántas actividades realice el estudiante. El sistema de certificados (mod_customcert) depende de la completitud del curso para emitir certificados automáticamente.

Repro Steps:

  1. Autenticar con token e7fe62...
  2. Llamar core_completion_get_course_completion_status para courseid=276
  3. El API retorna nocriteriaset

Acción requerida: Admin Moodle debe configurar Course completion en: Site administration → Courses → Course default settings → Enable completion tracking y luego en cada curso: Course administration → Course completion.

🐛 BUG-002: Actividades con completion tracking automático no registran visualización

ALTA

Ubicación: Curso 276 (Python) · Todas las actividades con completionview

Evidencia API:

GET core_completion_get_activities_completion_status?courseid=276&userid=154814

Solo 5 actividades tienen completion tracking (todas en Bienvenida):
  cmid:6929 "Sobre los docentes"        → state:0, requires: completionview
  cmid:6930 "Sobre los objetivos"       → state:0, requires: completionview
  cmid:6935 "Actividad grupal"          → state:0, requires: view + make 1 entry
  cmid:6980 "Cuestionario diagnóstico"  → state:0, requires: view + 1 attempt + grade
  cmid:7008 "Recurso Introductorio"     → state:0, tracking:1 (MANUAL!)

Actividades sin tracking (NO aparecen en la API):

  • 30+ notebooks de Módulo 1-3 (Lógica Booleana, Bucles, NumPy, Matplotlib, etc.)
  • Actividad "Proyecto Integrador" en la sección Cierre

Solo 5 actividades en la sección de Bienvenida tienen tracking, y todas muestran state:0 (no completadas). Las actividades con completionview deberían auto-completarse al ser visualizadas, pero no lo hacen. La actividad 7008 usa tracking MANUAL (tracking:1), que requiere que el usuario haga clic explícito en "Marcar como completada" — un paso que no está indicado en la UI.

Repro Steps:

  2. Abrir "Sobre los docentes" (cmid:6929)
  3. Verificar via API: state sigue siendo 0

🐛 BUG-003: Checkmarks falsos en UI — indicadores de progreso engañosos

ALTA

Ubicación: Curso 276 (Python) · Sección Bienvenida · Bloque de "checklist"

Evidencia:

UI muestra:    ✓ Revisar la información general del curso.
                ✓ Conocer a tus docentes y los objetivos del curso.
                ✓ Completar el cuestionario de diagnóstico.
                ✓ Participar en la actividad grupal de bienvenida.

API real:      state:0 para TODAS las actividades (cmid 6929, 6930, 6935, 6980)

Descripción: El contenido del curso incluye checkmarks verdes (✓) como texto estático embebido en HTML — no como datos dinámicos de completion tracking. El estudiante ve ✓ y cree que completó todo, pero el sistema registra state:0. Esto crea una falsa sensación de progreso. El estudiante no puede avanzar porque el sistema no reconoce las actividades como completadas, y no hay indicación visual de qué falta realmente.

4. Impacto en el Diploma Tracking System (DTS)

Impacto crítico en la integración DTS:
  • DTS usa core_completion_get_course_completion_status como proxy para detectar certificados
  • Ambos cursos activos de nelthor retornan nocriteriaset
  • → DTS nunca podrá detectar que estos cursos están completados
  • → Motor de reglas DTS nunca habilitará al estudiante para el examen integrador
  • → El flujo completo (cursos → certificados → elegibilidad → examen → diploma) está roto en el eslabón inicial
Recomendación técnica para DTS: Como fallback cuando core_completion_get_course_completion_status retorna nocriteriaset, DTS debería intentar core_completion_get_activities_completion_status — si todas las actividades tracked están en state:1, inferir el curso como completado. Si no hay actividades con tracking, DTS no puede determinar el estado y debe marcarlo como "indeterminado".
