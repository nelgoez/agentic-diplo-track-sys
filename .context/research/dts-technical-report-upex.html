1. Resumen Ejecutivo

El Diploma Tracking System (DTS) es un sistema de gestión de diplomaturas universitarias que articula el recorrido académico de los estudiantes a través de cursos modulares dictados en plataformas LMS, validando equivalencias mediante un motor de reglas configurable y gestionando el ciclo completo hasta la emisión del diploma.

Propósito: Automatizar la validación de prerrequisitos, habilitar la inscripción a exámenes integradores, y unificar los datos de múltiples plataformas (Moodle, SIU Guaraní) en un único panel de seguimiento.
Estado actual: Sistema operativo con 43 endpoints funcionales, 65 tests automatizados (100% pass), desplegado en Vercel con CI/CD vía GitHub Actions. Listo para presentación a stakeholders.

3.2 Patrones de Diseño

PatrónAplicación
Provider AbstractionInterfaces CertificateProvider y AcademicProvider permiten cambiar Moodle/Guaraní por cualquier LMS o sistema académico sin modificar el core.
Strategy PatternMotor de reglas con evaluación recursiva ALL/ANY sobre árboles de prerrequisitos. Inyectable vía dependency injection.
Middleware ChainHono middleware pipeline: Logger → PrettyJSON → CORS → Authenticate → RequireRole → Zod Validator → Handler.
Repository PatternSupabase Admin client como capa de acceso a datos, con RLS bypass para operaciones del sistema.
Event-driven (light)Auto-push a Guaraní tras registro de nota aprobatoria. Fire-and-forget con error handling.

3.3 Modelo de Datos

9 tablas principales en PostgreSQL con constraints de integridad referencial:

  • students — perfiles académicos con DNI, email, legajo
  • tracks — diplomaturas con créditos requeridos
  • courses — módulos dentro de una diplomatura, ordenados por order_index
  • certificates — certificados sincronizados desde Moodle (unique: student_id + course_id)
  • enrollments — inscripciones a diplomaturas + sub-estado de examen
  • prerequisite_rules — árbol de reglas auto-referenciado (ALL/ANY)
  • prerequisite_sources — cursos fuente para cada regla (M:N)
  • manual_overrides — excepciones con expiración opcional
  • integration_logs — auditoría de sincronizaciones externas

5. Plan de Negocio y Alcance

5.1 Propuesta de Valor

  • Unificación de datos: Sincroniza certificados de Moodle, estudiantes de Guaraní, y reglas de equivalencia en un solo sistema.
  • Automatización: Elimina procesos manuales de validación de prerrequisitos y registro de notas.
  • Trazabilidad: Cada acción queda registrada en integration_logs con timestamps y métricas.
  • Escalabilidad: Provider abstraction permite agregar nuevos LMS (Canvas, Blackboard) sin modificar el core.
  • Demo-ready: Modo mock permite mostrar el sistema completo sin depender de credenciales externas.

5.2 Flujo de Negocio Principal

1. Admin crea diplomatura + cursos + regla de equivalencias
2. Coordinador sincroniza padrón de estudiantes desde Guaraní
3. Coordinador sincroniza certificados desde Moodle
4. Estudiante ve dashboard: cursos aprobados, créditos, estado de habilitación
5. Motor de reglas evalúa elegibilidad en tiempo real
6. Estudiante habilitado → se inscribe a examen integrador
7. Coordinador registra nota → aprobado → push automático a Guaraní
8. Admin ve dashboard con métricas globales
